# Аудит безопасности ServerDeck Agent

Дата: 13 октября 2026 года. Методика: OWASP Top 10 (2021), статический анализ и безопасные offline-проверки текущего исходного кода.

**Результат: один подтверждённый обход защитной валидации исправлен и проверен на Windows 13 октября 2026 года.** Исходная серьёзность для offline E01 — низкая. Критических и высоких уязвимостей в проверенном коде не выявлено. Linux и нагрузка будущей службы требуют отдельной проверки.

Область: `cmd/`, весь Go-код `internal/` (включая generated types и embedded schemas), `go.mod`/`go.sum`, scripts сборки и bootstrap. Стек: Go 1.27.2, go-sqlite3 v1.14.52, jsonschema/v5 v5.3.1. Сверены требования ASEC-020/022/028 и модульная спецификация. Выполнен повторный проход с поиском обходов, альтернативных точек входа и завышенных выводов о последствиях.

Фактическая поверхность — четыре offline-команды: `version`, `sqlite-info`, `validate-config`, `check-contract`. Сетевые listeners, сопряжение, авторизация, постоянное хранилище и изменение сервера отсутствуют. Их отсутствие на данном этапе не классифицировано как уязвимость существующего сервиса.

## SD-SEC-001 — обход ограниченного подмножества схем модулей

**OWASP:** A04 Insecure Design / A08 Software and Data Integrity Failures. **CWE-20:** неправильная проверка входных данных. **Статус: Fixed**, исправление реализовано и проверено offline на Windows; это не закрывает общий Linux/E09 gate.

**Место исходного дефекта:** `declarations.go`, ранние `return nil` после `oneOf`, `const`, `enum` (до исправления строки 125–136). Исходные hashes сохранены в [source.sha256](evidence/security-audit-2026-10-13/source.sha256). Исправленный обход — [declarations.go](internal/contracts/declarations.go).

```go
if _, ok := s["const"]; ok {
    return nil
}
```

До исправления валидатор прекращал обход узла и не проверял соседние `properties`/`items` и их вложенные правила. Компилятор JSON Schema затем обрабатывал исходную схему целиком. Это позволяло провести через проверку запрещённые ключевые слова и рекурсивные ссылки, обойдя проверку глубины и числа посещений для пропущенного поддерева.

Безопасный пример `params_schema`, принятый CLI до исправления:

```json
{"const":{},"type":"object","properties":{"x":{"$ref":"#"}},"additionalProperties":false}
```

В исходном аудите подтверждены три варианта: `const` со вложенным `pattern`, `oneOf` с соседним `properties`/`pattern`, `const` со вложенным рекурсивным `$ref`. При исправлении новые тесты также воспроизвели обходы через `enum`, `items` и скрытую чрезмерную глубину. Контрольный пример с обычным вложенным `pattern` отклонялся и до исправления.

**Условия и последствия:** требуется передать специально составленный манифест локальной команде `check-contract module - FILE`. Сейчас это ложное успешное заключение проверки и нарушение запрета рекурсивных/произвольных схем из раздела 2 модульной спецификации. При будущем включении в службу появляется потенциальный риск чрезмерной работы компилятора/валидатора (ASEC-028). Рост CPU/RAM, зависание, удалённая эксплуатация и выполнение кода **не доказаны**. Общие ограничения JSON и запрет сетевой загрузки схем сохраняются.

**Выполненное исправление:** `properties`, `items` и schema-значение `additionalProperties` обходятся до раннего завершения по `const`/`enum`/`oneOf`, с теми же счётчиками глубины и посещений. `definitions`, `$ref` и ветки `oneOf` сохраняют свои проверки. Убраны повторные обходы object/array. Компиляция выполняется только после успешной общей проверки. Содержимое значений `const`/`enum` остаётся данными. Добавлены `TestDataSchemaSiblingGuards` (24 негативных сочетания и положительные примеры) и `TestDataSchemaSiblingDepth`; перед исправлением тесты падали на обходах, после — проходят. Повторный анализ schema-bearing keywords не выявил пропущенного поддерева в разрешённом подмножестве.

**Воспроизведение:** из корня проекта `python agent/evidence/security-audit-2026-10-13/reproduce.py`. Скрипт собирает текущий CLI; использует синтетические манифесты, не запускает и не регистрирует модули; завершается ошибкой, если опасная схема принята. [Исходные результаты](evidence/security-audit-2026-10-13/results.txt) сохранены. [После исправления](evidence/security-audit-2026-10-13/results-fixed.txt) все пять входов, включая `enum`, дают exit 1 / `SCHEMA_MISMATCH`.

## Проверки и ограничения

На Windows amd64, Go 1.27.2, `CGO_ENABLED=1`, существующий GCC: **прошли** `go mod verify`, `go vet ./...`, `go test -count=1 ./...`, `go test -race -count=1 ./...`; все пакеты успешны. Команды выполнялись из `agent/` с `GOTOOLCHAIN=local`, `GOPATH=D:/Projects/ServerDeck/.tools/gopath`, `GOCACHE=D:/Projects/ServerDeck/.tools/gocache`, исполняемый Go — `../.tools/go/bin/go.exe`. Обычные тесты не покрывали обнаруженные сочетания schema keywords.

`govulncheck` не установлен; запрос официальной базы из терминала завершился ошибкой разрешения хоста. Веб-проверены [история Go](https://go.dev/doc/devel/release), [политика безопасности go-sqlite3](https://github.com/mattn/go-sqlite3/security) и [документация jsonschema v5.3.1](https://pkg.go.dev/github.com/santhosh-tekuri/jsonschema/v5@v5.3.1). Это не заменяет машинную проверку достижимости известных CVE и встроенного SQLite.

Остаётся: в доступном сетевом окружении выполнить `govulncheck ./...` и проверку native SQLite; отдельно закрыть Linux/cgo amd64/arm64 gate. Linux, systemd, реальные права/файловые гонки, TLS, подписи, восстановление и нагрузка в этом аудите не испытывались. Результат не является заключением о готовности выпуска.
