# E04: общий сбор и снимки

13 октября 2026. Нормативные границы: AFR-012/013, AFR-015–AFR-018, AFR-022–AFR-026, AFR-070; ASEC-001/004/018/028/030. Этот документ описывает реализацию `internal/metrics`, не меняет согласованные права. История/события — E05, NVML/Docker/security — E06, сигналы и ICMP — E07. Их отсутствующие capabilities не включены.

## Поток данных и время

Native `serve --config` после открытия listeners создаёт Linux collector и Engine. Scheduler работает без клиентов; один worker на `system`, `cpu`, `memory`, `network`, `filesystems`, `processes`. Рабочие функции не вызывают SQL, HTTP, shell, sudo, изменение файлов, сигналы или чтение cmdline/environ. Ошибка чтения boot ID отключает metrics capabilities, сохраняя остальные API; вымышленный boot ID не создаётся.

Интервалы: CPU/RAM/network 2с; процессы 5с, с активным потребителем 2с; ФС 15с; система и CPU/network metadata 60с со сбором новых ресурсов при обнаружении. Сведения CPU/network имеют собственный `observed_at`, не обновляемый выдачей cached record. Source `linux.<block_id>`, реестр рядов `series_schema=1`. `cpu_summary` однозначно связывает aggregate CPU resource_id с числом logical CPU; неизвестное число null. CPU `throttle_events` (count, cumulative core_throttle_count) и process `uptime_seconds` (second, kernel uptime minus start_ticks/CLK_TCK) дополняют реестр v1. Счётчик throttling не подменяет boolean текущего throttling: при отсутствии надёжного источника текущего состояния — unsupported/CURRENT_STATE_UNSUPPORTED.

Engine применяет UTC для отображения, монотонное время для интервалов, TTL, производных и stale. После трёх интервалов без нового успешного значения freshness=stale; отказ источника сохраняет last-good value/measurement с отдельным availability и attempted_at. Ноль остаётся валидным измерением. Первая производная/reset/нулевой знаменатель не становятся нулём. Сдвиг UTC назад либо расхождение с monotonic >1с создаёт segment_id, сбрасывает baselines и страницы; запоздавший результат старого сегмента отбрасывается. При запуске меняется agent_run_id. Agent identity не вычисляется из hostname/boot.

CPU busy исключает idle/iowait, включает steal; guest повторно не складывается. PSI — kernel avg10, источник и окно явно здесь зарегистрированы. Частоты sysfs переводятся kHz→Hz; температурный профиль читает только явно распознанные CPU thermal zones x86_pkg_temp/cpu-thermal/cpu_thermal и hwmon coretemp (Core/Package)/k10temp (Tdie, без подмены Tctl), максимум доступных CPU zones, millidegree→celsius. Неизвестные датчики не угадываются. Расширение прочих профилей hwmon/ARM требует отдельных fixtures/проверки ABI; отсутствие профиля не объявляет отсутствующим оборудование.

RAM used=MemTotal−MemAvailable, без подмены MemAvailable на MemFree. Нулевой swap имеет zero capacity/absent для процента, а нулевой использованный объём — available. ФС: used=(blocks−bfree)×frsize, available=bavail×frsize, reserved=(bfree−bavail)×frsize; used%=used/(used+available). Корень `/` включён даже для overlay; остальные служебные ФС скрыты. Главный диск определяется только записью mountpoint `/`, при его ошибке другой диск не выбирается. Изменившийся mountinfo отбрасывает собранную выдачу.

Сеть: boot+net namespace+ifindex+наблюдаемая generation; исчезновение/reset меняет resource_id. Sum rx/tx rates включает только объявленный набор non-loopback интерфейсов; `network_summary.included_resource_ids` и warning=BRIDGE_VETH_DOUBLE_COUNT_POSSIBLE обязательны. Это не оценка уникального внешнего трафика. `link_load_percent` использует max(rx,tx)×8/link_bps, без знаменателя при неизвестной скорости. Metadata включает operstate, адреса, MTU, DNS, duplex, link_bps и IPv4/IPv6 routes. Строка маршрута v1: `<interface> ipv4 <поля /proc/net/route без interface>` либо `<interface> ipv6 <поля /proc/net/ipv6_route без последнего interface>`; gateway сохраняется в соответствующем поле kernel ABI, IPv4 hex little-endian в целевых amd64/arm64. Эти строки — данные, не команды. Настройки DNS читаются локально; внешних проверок IP/DNS/доступности нет.

## Процессы, запросы и доставка

process_ref — SHA256-derived bounded reference от boot/PID/start_ticks/pid namespace; остальные поля идентичности возвращаются отдельно. Stat и namespace проверяются до/после metadata чтения; исчезновение/reuse исключает запись, частичная видимость отмечена явно. CPU percent может превышать100; host percent вычисляется только при одинаковом числе online CPU на границах окна. Точное несэмплированное изменение CPU внутри окна не обещается. UID — проверенный числовой владелец, без блокирующего NSS lookup. Start_ticks сохраняет kernel start identity; UTC начала не выдумывается после перевода часов. Parent связывается только с процессом того же снимка, unit — с доступным cgroup; отсутствие container_id не доказывает отсутствие контейнера.

`snapshot.get` и `processes.list/get` доступны через существующие authenticated HTTPS/local queries. WSS snapshot заменяемый, без ACK/cursor и очереди старых снимков; summary выдаётся раз в5с, detail раз в2с. Ошибка/limit возвращается безопасно, не превращается в пустой успех. Процессный summary содержит CPU top10, detail максимум100; полный ограниченный набор и RSS top доступны через процессы list с сортировкой. При PAGE_REQUIRED snapshot.partial=true. Фильтрация и сортировка выполняются до страницы, tie-break по process_ref.

Process pagination хранит неизменяемую общую выборку: TTL30с, ≤2 revisions на доверенного владельца. HMAC cursor связан с Agent, snapshot revision, инициатором, query/filter/sort; limit можно изменить. Чужой actor, изменённая сортировка, restart/истёкший снимок не продолжают страницу. Локальный owner берётся из OS peer, сетевой — из credential, не из JSON. Query lease10с, WSS lease обновляется только для detail с processes; disconnect освобождает свой lease. Чтение не вызывает самостоятельный сбор.

## Численные границы и отказы

- Входной файл источника ≤1МБ; process stat16КБ, status64КБ, cgroup16КБ; proc directory scan ≤65536 entries. Некорректные числа/UTF-8/переполнение не принимаются.
- ≤256 logical CPUs плюс aggregate; ≤256 interfaces; ≤256 видимых mounts. Processes ≤4096 и ≤4МБ encoded records на одну выборку. Ограничение отражается reason/partial/coverage, не выдаётся за полный список.
- ≤64 query/WSS lease owners; ≤64 page owners, ≤2 revisions каждого, ≤32 различных retained revisions глобально. При исчерпании возвращается LIMIT_EXCEEDED, незавершённая страница не подменяется другой. Encoded retained generations ≤128МБ; это не утверждение о размере Go heap/RSS, который ещё измеряется в E12.
- Одна очередь задания и один активный worker на источник; канал результатов6. Зависший worker не размножается. Обработанная panic превращается в source_error без текста panic; fatal Go/cgo crash не обещан изолированным.
- statfs отдельно ограничен четырьмя реальными вызовами и одним outstanding на observed mount; ожидание10мс не освобождает native slot. Остальные mounts остаются с индивидуальными значениями/ошибками, root проверяется первым. Поздний ответ сохраняет фактическое время собственного вызова. Зависшие системные вызовы нельзя остановить context cancellation; остановка Engine не ждёт их бесконечно. Четыре зависших вызова дают SOURCE_BUSY остальным mounts; остальные источники продолжают работу.
- Из исходников WSL ничего автоматически не копируется обратно. Сборка/test/cache/SQLite fixture DB только в Linux ext4-копии; исходные/финальные SHA256 проверяются runbook. Monitoring не зависит от успешной записи аудита, но сетевое чтение сохраняет авторизацию E03.

Полный ответ ограничен существующим codec1МБ. Слишком большой snapshot отклоняется LIMIT_EXCEEDED; клиент выбирает blocks/resource_ids или process pages. Source failure не означает OFFLINE. Диагностика содержит только перечисленные коды, не произвольные ошибки/path/контент. Mount source с userinfo (`@`) редактируется.

## Источники технических решений

[Kernel proc ABI](https://www.kernel.org/doc/html/latest/filesystems/proc.html): CPU guest и возможное уменьшение iowait, meminfo, процессные поля. [proc_pid_stat](https://www.man7.org/linux/man-pages/man5/proc_pid_stat.5.html): номера полей, starttime и sysconf(_SC_CLK_TCK); CLOCK_TCK получен через cgo/libc, не принят равным100 на машине. [statfs](https://www.man7.org/linux/man-pages/man2/statfs.2.html) и [statvfs](https://www.man7.org/linux/man-pages/man3/statvfs.3.html): blocks/frsize/bavail и reserved space. [Thermal sysfs](https://kernel.org/doc/html/v5.7/driver-api/thermal/sysfs-api.html), [x86 package sensor](https://kernel.org/doc/html/v6.1/driver-api/thermal/x86_pkg_temperature_thermal.html), [coretemp](https://www.kernel.org/doc/html/latest/hwmon/coretemp.html), [k10temp](https://www.kernel.org/doc/html/v5.15/hwmon/k10temp.html), [throttle counters](https://www.kernel.org/doc/html/latest/admin-guide/thermal/intel_thermal_throttle.html): единицы/распознаваемый профиль. Применимость подтверждается только обнаруженным ABI/fixtures, не названием дистрибутива.

Результаты и открытые критерии — в [E04 evidence](evidence/E04-wsl-2026-10-13/README.md) и журнале требований; WSL не подтверждает матрицу физических Linux/ARM/GPU. systemd watchdog/production restart lifecycle остаются E11/E12.

CPU PSI уточнение: [официальный Linux6.6 PSI ABI](https://www.kernel.org/doc/html/v6.6/accounting/psi.html) определяет system-level CPU full как undefined; compatibility zero не выдаётся как измеренный процент. `psi_full_percent` возвращает null/unsupported/SYSTEM_CPU_FULL_UNDEFINED, `psi_some_percent` использует avg10. TestSystemCPUFullPSIZeroIsUndefinedNotAvailable проверяет обе ветви. Это исправление семантики AFR-013/022, а не изменение продуктовой гарантии.

В E04 blocks выбирает только зарегистрированные system/cpu/memory/network/filesystems/processes. Неизвестный selector возвращает SOURCE_UNAVAILABLE (HTTP и WSS), а не полный пустой снимок; будущие adapters регистрируются вместе с реализацией своих этапов. Отказ уже зарегистрированного источника сохраняет его блок с availability/reason, не блокирует остальные.

Для capacity чтения открывается O_PATH/CLOEXEC/NOFOLLOW FD; его /proc/self/fdinfo mnt_id проверяется против mountinfo ID, затем вызывается Fstatfs по этому FD. Скрытый overmount не получает статистику видимого mount и исключается из выдачи; root выбирается среди видимых records. Дополнительная сверка mountinfo после сбора сохранена. [O_PATH/Fstatfs](https://www.man7.org/linux/man-pages/man2/open.2.html), [fdinfo mnt_id](https://www.man7.org/linux/man-pages/man5/proc_pid_fdinfo.5.html); ABI доступен раньше минимального kernel5.6. TestNativeFilesystemDescriptorBindsExpectedMount проверяет настоящий FD и неправильный expected mount ID без изменения mounts хоста.
