# E06: NVIDIA, Docker и источники безопасности

Состояние 15 октября 2026: реализована доступная часть E06; этап целиком открыт. Нормативные требования: AFR-002/014/020/021/028/034, ASEC-019/028. Наличие адаптера не подтверждает его работу на реальном GPU или daemon.

## Реализация и ограничения

Общий Linux collector запускает gpu/docker/security в отдельных ограниченных workers вместе с E04 источниками. GPU динамика — 2 секунды; NVML static metadata и порог устройства кэшируются 60 секунд с исходной временной меткой. Docker/security — 15 секунд. Зависший нативный NVML-вызов не создаёт повторные workers; авария native-кода в общем процессе остаётся риском принятой архитектуры. Изоляция driver crash и реальный hang ещё не проверены.

Поле `cuda` означает поддерживаемую драйвером версию CUDA по NVML SystemGetCudaDriverVersion. GPU использует закреплённый NVIDIA go-nvml v0.13.4-1 и доверенный абсолютный путь root-owned NVML. Не устанавливает драйверы. Ограниченный read-only nvidia-smi CSV fallback не выдаёт отсутствующие поля за ноль. UUID определяет ресурс. Power переводится mW→W, VRAM хранится целым числом байтов. Максимум 32 GPU и 128 процессов на GPU и 512 суммарно; превышение явно помечается. PID не становится process_ref: этого недостаточно для безопасной идентификации процесса. История разделяет серии NVML и SMI; агрегирует GPU power/temperature/VRAM с максимумами. Температурное правило использует доступный свежий порог того же GPU, без выдуманного default. Для новых БД правило включено; уже сохранённое пользовательское enabled сохраняется и меняется штатным audited rules.put.

Docker читает только фиксированные GET по локальному Unix-сокету. `adapters.docker_socket` задаёт явный rootless путь; TCP, DOCKER_HOST, redirects и raw proxy отсутствуют. Проверяются inode сокета и UID peer через SO_PEERCRED. API согласуется в диапазоне 1.40–1.56. Ответ ограничен 2 MB, общий poll — 2 секунды; до 256 контейнеров, stats/inspect до 16 за poll по кругу. Вложенные GPU/Docker метрики сохраняют отдельные process-local монотонные позиции вне JSON; Snapshot пересчитывает stale/partial без опоры на перевод wall clock и распространяет ошибку источника. Метрики сохраняют собственные измерения и ожидаемый интервал; неполная health coverage не выдаёт точный ноль проблем. CPU требует положительного приращения system counter; warming/reset даёт null. Memory working set требует известного inactive_file/total_inactive_file; неизвестный метод и unlimited limit не выдаются за точные значения. Из inspect не публикуются Env/Config, из labels только Compose project/service. Реальные Docker rootful/rootless daemon ещё не проверены.

SSH profile распознаёт ограниченный OpenSSH auth_log формат с RFC3339 или локальным RFC3164 timestamp. PAM companion не увеличивает счётчик повторно; успешный вход — info observation, без username/raw log. Неизвестный sshd message означает partial coverage. auth.log открывается O_NOFOLLOW как regular file; cursor содержит dev/inode/offset/source generation/sequence и HMAC ограниченного хвоста, без сырого текста. Generation сохраняется до обработки нового inode/перезаписи. Rename rotation дочитывает auth.log.1, copytruncate обнаруживается по размеру/anchor. Потеря подтверждения сохранения cursor обрабатывается повторной загрузкой durable состояния; E05 Source/Position дедуплицирует наблюдения. Первое включение начинается с EOF, не воспроизводит старую историю. Не обещается обнаружение любой внешней перезаписи вне bounded anchor или восстановление всех уже удалённых архивов.

При отсутствии auth.log используется ограниченный journalctl JSON с opaque cursor, system journal, _COMM=sshd и _UID=0. Потеря/вакуум cursor не означает «всё чисто»: coverage остаётся недоступной. После отдельного успешного bounded tail probe с доверенными метаданными сначала надёжно сохраняется AUTH_SOURCE_GAP observation, затем cursor переводится на подтверждённую последнюю запись. Потеря подтверждения повторяет тот же event ID; неуспех probe не сбрасывает cursor. Новая quiet coverage не объявляется в poll восстановления. Partial-line enrollment пропускает незавершённый старый фрагмент с partial coverage. Реальная journal vacuum процедура и полный Ubuntu/Debian format matrix пока не проверены.

Firewall nft list tables — наблюдение видимости, не доказательство эффективности правил. Этот ограниченный профиль всегда оставляет общее coverage=partial (либо unavailable), даже когда все четыре источника доступны. SSH sessions читаются loginctl, Fail2ban — фиксированными status запросами (до 64 jails, ограниченные bans). Unknown/denied/absent состояния отдельных источников представлены source_available; чужие настройки, группы и права не меняются. Полнота firewall backends, реальный Fail2ban и наблюдение всех типов блокировок ещё требуют завершения V-ADAPTER.

## Проверка и оставшаяся работа

Команды и фактические результаты: [E06 evidence](evidence/E06-wsl-2026-10-15/README.md), [BUILD](BUILD.md). Fixtures проверяют реальный Unix-сокет и файловую ротацию, но не заменяют daemon/hardware проверку. E06 не закрыт: нужны V-GPU на NVIDIA hardware/driver, изолированная native-fault процедура, настоящий Docker rootless/rootful и security matrix Ubuntu/Debian; также реальная journal vacuum recovery и полнота security adapters. E07 автоматически не начинается.

## Первичные источники

- [NVML Device Queries](https://docs.nvidia.com/deploy/nvml-api/latest/api/group__nvmlDeviceQueries.html), включая power units, temperature threshold и возвраты unsupported/permission.
- [NVIDIA go-nvml v0.13.4-1](https://github.com/NVIDIA/go-nvml/tree/v0.13.4-1), Apache-2.0; лицензия в licenses/.
- [nvidia-smi](https://docs.nvidia.com/deploy/nvidia-smi/), CSV selective query; fallback не обеспечивает полноту NVML.
- [Docker Engine API](https://docs.docker.com/reference/api/engine/), version negotiation и stats; поддерживаемый диапазон является ограничением этого адаптера.
- [OpenSSH 8.9p1 auth.c](https://raw.githubusercontent.com/openssh/openssh-portable/V_8_9_P1/auth.c), auth_log formatter.
- [Fail2ban 0.11.2 beautifier.py](https://raw.githubusercontent.com/fail2ban/fail2ban/0.11.2/fail2ban/client/beautifier.py), status labels. Проверка formatter не равна проверке установленного daemon.
- [journalctl](https://www.freedesktop.org/software/systemd/man/255/journalctl.html); фактическая Ubuntu версия 249.11, её доступные flags должны подтверждаться evidence окружения.
