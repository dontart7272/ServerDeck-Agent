# ServerDeck: краткое описание

Актуализация интеграции 12 октября 2026 года: [дополнение клиентских контрактов](<Документация ServerDeck Agent/12. Согласование с клиентом.md>) задаёт действующие правила Agent для root/прав/модулей/корней/PURGE/localhost/истории/аудита и фоновой работы. Для этих границ прежние формулировки применяются с дополнением; макеты и старые обсуждения их не переопределяют.

## Проблема

Пользователю нужно быстро и удобно следить за своими удалёнными серверами со смартфона, проверять их доступность и управлять установленными утилитами.

Обычное приложение-терминал эту задачу не решает: со смартфона неудобно вводить bash-команды и интерпретировать их текстовый вывод. При этом полноценный терминал всё равно нужен для нестандартных задач и восстановления сервера.

## Целевая аудитория

Владельцы собственных или арендованных серверов (удалённых или домашних), которым нужно наблюдать за ними и управлять ими без доступа к ПК.

## Ценность продукта

- Состояние сервера в структурированном виде: CPU, GPU, RAM, диски, сеть, процессы, сервисы, логи.
- Графики и история метрик вместо разбора вывода команд.
- Управление установленными утилитами (БД, прокси/VPN-туннели, файловые хранилища и т. п.) через удобный интерфейс.
- Расширяемость: поддержку новой утилиты можно добавить модулем, не меняя само приложение.
- Быстрый переход к SSH-терминалу выбранного сервера, когда готового интерфейса недостаточно.

## Цель продукта

Создать нативное Android-приложение на Kotlin для мониторинга и управления своими серверами и установленными на них утилитами. Пользовательский интерфейс реализуется на Jetpack Compose.

## Состав системы

| Компонент | Назначение |
|---|---|
| Клиент ServerDeck | Нативное Android-приложение на Kotlin и Jetpack Compose; отображает данные и инициирует операции |
| ServerDeck Agent | Постоянно работающий сервис на сервере: собирает и нормализует данные, предоставляет API, выполняет только заранее определённые разрешённые операции |
| Модули | Пара «серверный модуль агента + клиентский UI-пакет», связанные общим `module_id` и версионированным контрактом |
| SSH-терминал | Независимый от агента канал интерактивной работы; на Android — запуск SSH-сессии выбранного сервера в Termux |

## Ключевые принципы

- Клиент запрашивает известную операцию с параметрами, агент сам проверяет права и определяет способ выполнения. Endpoint для произвольных команд отсутствует.
- Интерфейс модулей описывается декларативным JSON, устанавливается в клиент локально и отрисовывается из встроенных компонентов Jetpack Compose. Описание определяет структуру, порядок блоков и привязки к данным; данные приходят отдельными ответами API агента. Исполняемый код от модулей и серверов не принимается.
- Базовые экраны (подключение, секреты, установка модулей, подтверждение опасных действий) встроены в клиент.
- Агент работает без центрального аккаунта, но с обязательной аутентификацией устройства (pairing, отзывные токены) по HTTPS/WSS.
- Токены устройств хранятся в зашифрованном виде с ключами Android Keystore. SSH-пароли, приватные ключи, парольные фразы и пароль sudo существуют только в памяти на время конкретной операции.
- Недоступные данные показываются как отсутствующие с причиной, а не как нулевые значения.
- Базовые экраны и страницы модулей используют общую тему и встроенные компоненты приложения. Макеты Stitch задают визуальный образец; их экспорт не является реализацией клиента.

## Технологический стек (предварительный)

| Область | Выбор | Статус |
|---|---|---|
| Язык клиента | Kotlin | Принято |
| UI клиента | Jetpack Compose, общая тема и собственные переиспользуемые компоненты | Принято |
| Навигация | Навигация между экранами Compose по карте экранов; конкретная библиотека уточняется при реализации | Подлежит уточнению |
| Интерфейс модулей | Валидируемый JSON и встроенный реестр компонентов Compose; данные и действия через API агента | Принято |
| Возможности Android | Android Keystore, системная биометрия, SSH-транспорт и запуск Termux через Intent | Принято; библиотеки уточняются |
| Распространение клиента | Подписанный APK в GitHub Releases | Принято |
| Агент | Python + FastAPI | Предпочтение, требует сравнения с Go по критериям распространения |

## Границы продукта

- Без обязательной регистрации и центрального облачного аккаунта ServerDeck.
- Без встроенного ИИ-помощника.
- Без исполнения произвольного удалённого кода в клиенте.
- Целевая платформа клиента — Android. Поддержка дополнительных платформ требует отдельного решения и не является обязательством текущей архитектуры.
