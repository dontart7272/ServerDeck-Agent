# Порядок реализации Agent

12 октября 2026 года. Этот файл дополняет [корневой AGENTS.md](<../../AGENTS.md>) ссылками и последовательностью; не заменяет его, AFR или ASEC.

## 1. Перед первым кодом

Прочитать [готовность и препятствия](<10. Противоречия и готовность.md>) и входной gate этапа E01 в [плане](<9. План реализации.md>). Проверить фактическое состояние: на дату оформления Go-модуля, кода, Git checkout и CI в корне нет. Структура в архитектуре — проектируемая. Не создавать выдуманные статусы реализации/испытаний.

Нормативные источники: [AFR](<2. Функциональные требования.md>), [ASEC](<4. Требования безопасности.md>), [API](<3. API и форматы данных.md.md>), [модули](<5. Модульная система.md.md>), [конфигурация](<7. Пример конфигурации.md.md>), [архитектура](<8. Архитектура и обслуживание.md>). Р01–Р25 приняты; не открывать повторно Go/SQLite/root/PURGE/HTTPS/токены/интервалы. Старый клиентский helper не является разрешением повышать права.

## 2. Для каждого изменения

1. Выбрать AFR/ASEC, прочитать приёмку/проверку и конкретные разделы спецификации. Учесть межкомпонентный контракт и применимые локальные инструкции.
2. Сверить открытые gates: неподтверждённую гарантию не превращать в код по догадке. Рутинные решения допускаются в согласованных границах. Существенное расширение прав/ослабление гарантий сначала согласовать.
3. Реализовать связный блок и негативные сценарии. HTTP/CLI используют один application service и один audit/operation guard. Не писать второй обходной путь изменения БД/файлов.
4. Обновить schema/examples/config/спецификацию при изменении контракта, совместимость major/minor проверить отдельно. Не считать семантические проверки выполненными только по JSON Schema.
5. В [журнал](<11. Журнал проверки требований.md>) добавить реализацию, окружение/версию, дату, точную команду/шаги, ожидаемый/фактический результат и артефакт. Частичное покрытие указывать явно.

## 3. Проверки после появления Go-модуля

E01: `agent/` теперь существует, module path `serverdeck.local/agent` подтверждён пользователем. Реальные команды, pins и границы проверок — [agent/BUILD.md](<../../agent/BUILD.md>), evidence — [Windows checks](<../../agent/evidence/E01-windows-checks.txt>). Не запускать службу или E02 по факту успешных Windows unit tests; Ubuntu WSL2 amd64 cgo/smoke/race и arm64 cross-build/ELF проверены; по решению пользователя 13 октября 2026 native ARM smoke/tests/race перенесены в E12. E01 закрыт по уточнённым критериям; E02 реализован и проверен по отдельному поручению пользователя: [storage/operations](<../../agent/STORAGE.md>), [E02 evidence](<../../agent/evidence/E02-wsl-2026-10-13/README.md>). E03 выполнен по отдельному поручению: [auth/transport](<../../agent/AUTH-TRANSPORT.md>), [E03 evidence](<../../agent/evidence/E03-wsl-2026-10-13/README.md>). E04 автоматически не начинать. Сетевые тесты только loopback/private fixtures; наличие serve не разрешает публичную установку незавершённого продукта. ARM64 остаётся экспериментальным до нативных проверок. [Linux evidence и команды](<../../agent/evidence/E01-wsl-2026-10-13/README.md>) не доказывают обычный VPS/systemd или всю матрицу.

Из `agent/`: gofmt изменённых Go-файлов, `go vet ./...`, `go test ./...`; для конкурентного кода `go test -race ./...` на поддерживаемом Linux/cgo окружении. Linux-интеграция отдельно от Windows unit checks. Go/cgo/зависимости закрепить в E01; до этого эти команды — будущий порядок, а не существующий CI.

Контракт/документация: из корня `pwsh -NoProfile -File "Документация ServerDeck/Документация ServerDeck Agent/tools/check-docs.ps1"`. Валидатор проверяет ссылки/идентификаторы/JSON-примеры/структуру схем; не доказывает файловую безопасность, SQLite durability, TLS или поведение Agent. Расширять проверки только при изменении затронутого контракта/обнаружении дефекта.

## 4. Завершение блока

«Согласовано» относится к требованиям; «специфицировано» — к детализации; «реализовано» — к существующему коду; «проверено» — к конкретному результату на заявленном окружении. Успешный schema check не повышает AFR автоматически до «проверено». Заглушка GPU не заменяет реальную NVIDIA. Контейнер не заменяет host systemd/ядро/права. Существенный непроверенный gate остаётся ограничением готовности даже при проходящих unit tests.
