## 2. BLOCK-FS: строгая защита от внешней гонки

Связаны AFR-040, AFR-043, AFR-046, AFR-049 и ASEC-014–ASEC-017. Требования одновременно требуют защищённого пути, текущей версии и отсутствия молчаливой потери внешнего изменения. FD+openat2 защищает разрешение; stat/hash перед rename не объединяет сравнение текущего inode/контента и замену в одну операцию. Переименование родителя после проверки и запись через уже открытый внешним процессом FD требуют отдельного доказательства. `RENAME_NOREPLACE` защищает отсутствие destination, но не выполняет compare-existing-version-and-replace.

Это вывод из [openat2](https://manpages.debian.org/bookworm/manpages-dev/openat2.2.en.html) и [renameat2](https://manpages.debian.org/bookworm/manpages-dev/renameat2.2.en.html), проверено 12 октября 2026; не утверждение, что уже найден универсальный безопасный алгоритм для всех ФС. Проверки до/после не доказывают отсутствия ущерба в промежутке. Advisory flock не координирует произвольный SSH-writer.

**Рекомендация в текущих требованиях:** сохранять строгую гарантию; E08 допускает конкретный mutation-примитив только после Linux race tests и объяснения условий безопасности. Невозможность доказать безопасность → SAFETY_UNAVAILABLE/capability unavailable. Весь файловый менеджер остаётся в плане, заглушку записи нельзя считать исполнением AFR-046. Создание нового имени без замены проще, но parent/mount/alias guards также проверяются.

**Альтернатива, требующая решения пользователя до реализации:** ограничить гарантию внешнего конфликта обнаруживаемыми изменениями до публикации и явно признать остаточную гонку; либо ограничить запись согласованными каталогами/кооперативными writers/режимом обслуживания. Это меняет поведение или гарантии, поэтому здесь НЕ принято. Не ослаблять AFR молча ради реализации E08. Если строгая модель не реализуема на требуемой ФС, сначала представить пользователю результаты и конкретную альтернативу.

Статус: блокирует заявление готовности спорных файловых mutations, не E01–E07. Закрытие: доказанный алгоритм+условия+V-FILE или прямое согласованное изменение требований. Внешний root/злонамеренный общий UID уже вне обещанной изоляции, но обычная конкурентная SSH-запись из модели не исключена.

## 4. Устранённые трактовки противоречий

ASEC-011 запрещает изменения без аудита, ASEC-031 допускает первичную установку/внешнее emergency maintenance. Это разные доверенные пути: штатный local CLI вызывает тот же guard, аварийная процедура требует реальных OS-прав и обозначает пробел. HTTP/модульного bypass нет. При ENOSPC телефон не очищает файл в обход guard.

AFR-036 ограничивает аудит, AFR-039 сохраняет незавершённые операции: audit stream ротируется, единственное operation intent/state отдельно сохраняется до reconciliation; при пределе новые изменения блокируются. Нет бесконечной БД и нет ложного terminal failure ради ротации.

AFR-068 требует автовозврат, ASEC-026 запрещает возврат старых разрешений: preflight допускает только проверенную rollback-compatible пару со security floor. Несовместимая миграция без возврата остаётся отдельным maintenance plan, как уже принято. Не вводится новый «всегда откатится» режим.

AFR-053 допускает принудительную остановку managed module, AFR-041 запрещает автоматический TERM→KILL пользовательского процесса: lifecycle модуля и именованные пользовательские сигналы различаются; общий signal API не эскалирует.

AFR-004 разрешает root, ASEC-015 сохраняет собственные guards: OS-полномочия не отменяют серверную политику. Общий UID/root не считаются изоляцией. Установка с sudo не меняет selected runtime user.

## E08: согласованная модель внешних writers —15 октября2026

Пользователь прямо согласовал рекомендованную модель: «Согласовать рекомендованную модель». Это заменяет прежнюю строгую гарантию BLOCK-FS для конфликтов версий, а не требования защиты собственных объектов Agent.

AFR-040/043/046/049 и ASEC-017 применяются так: Agent сериализует свои конфликтующие операции, проверяет ожидаемую идентичность/версию непосредственно перед публикацией и при обнаруженном конфликте отказывает без замены. Готовый результат публикуется атомарно в пределах одной ФС; перед заменой сохраняется предыдущая проверенная версия для восстановления. Между последней проверкой и публикацией остаётся гонка с внешней записью/rename через SSH, включая ранее открытый writable FD. Универсальный compare-and-swap содержимого Linux не обещается; сохранённая копия не объявляется точной версией, записанной внешним writer в этот промежуток.

Существующее имя не заменяется без отдельной политики/подтверждения. Cross-FS остаётся copy/verify/отдельный trash источника с честным partial/unknown. При неопределённости побочный эффект автоматически не повторяется. Аудит до effect, сохранность исходника при ENOSPC, запреты secrets/own objects/ancestors, права ОС, traversal/aliases/mount guards и отдельный PURGE не ослаблены. Технические gates безопасного пути/inventory остаются отдельными; эту новую модель нельзя использовать как разрешение обходить их.

BLOCK-FS как продуктовая развилка решён данным согласованием. Реализация и V-FILE ещё должны быть выполнены; прежний контрпример stat+rename теперь проверяет объявленное ограничение, а не выдуманную гарантию отсутствия внешней гонки.

## E08: согласованная модель обслуживания и дескрипторов —15 октября2026

Пользователь прямо согласовал рекомендованную модель для AFR-042/043 и ASEC-014/015. Собственные корни, конфигурацию, ключи, БД и рабочие каталоги Agent администратор перемещает/перестраивает через SSH только после остановки Agent и его выполняющихся файловых действий. Обычные пользовательские файлы можно изменять параллельно, с ранее согласованным остаточным окном внешнего конфликта.

Разрешённый объект привязывается к проверенному дескриптору после openat2 BENEATH/NO_SYMLINKS/NO_MAGICLINKS/NO_XDEV. Перенос уже разрешённого пользовательского каталога внешним администратором может привести к неопределённому результату; непрерывное нахождение этого объекта под строковым именем корня не гарантируется. Это не разрешение клиенту обходить root policy: операции Agent сериализуются с изменением политики, относительные компоненты проверяются один раз, возвращаемые объекты повторно открываются под разрешённым root; при потере привязки — unknown, без слепого повторения.

API по-прежнему запрещает собственные объекты Agent, их aliases и разрушительные операции над необходимыми предками, также при root. Собственные каталоги защищены inode-идентичностями, каталогами-предками и private namespaces; обычные hard links и вложенные/поддеревные bind mounts не разрешаются обходом. Проверки закреплённых bootstrap paths/живых identities и опубликованного inventory сохраняются. Смена/потеря доказательства закрывает допуск. Эта модель заменяет прежнее требование устойчивости к произвольному одновременному административному переносу собственных рабочих деревьев; нарушение процедуры обслуживания не объявляется поддержанным сценарием.

TECH-FS-READ/мутации на общей ФС теперь реализуются в этих согласованных условиях. Успешные проверки старого строгого FS-deny профиля не заменяют новые V-FILE tests. Полный E08 нельзя закрыть до окончания реализации и проверки.
