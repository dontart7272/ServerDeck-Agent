# Дополнение клиентских контрактов

12 октября 2026 года. Применяет уже принятые Р01–Р25 и AFR/ASEC к прежним клиентским FR/NFR/UC/экранам. Это действующее дополнение, а не предложение отменить согласованные решения. Android-приложение пока не реализовано. Остальной клиентский UX здесь не перепроектируется.

## 2. Обязательные клиентские состояния

Показывать availability отдельно от freshness, last-successful measurement отдельно от server response. Valid zero/absent/unsupported/permission_denied/source_error/stale различаются. Данные разных boot/resource/schema/clock segments не склеиваются. Process CPU может превышать100% при выбранной per-core нормализации; подпись/host_percent снимают неоднозначность.

Version conflict показывает текущее состояние и новый prepare; не предлагает «повторить вслепую». operation unknown/result_pending не считается ни success, ни guaranteed failure. signal_sent и exit_observed различаются. Для cross-FS partial показываются обе стороны/источник. SAFETY_UNAVAILABLE не маскируется активной кнопкой записи, пока BLOCK-FS не закрыт для данного примитива.

Revoke другого/самого себя, KILL, PURGE, расширение roots, снижение budget/retention, module remove/purge/dependencies используют native confirmation с plan consequences. UI module не может скрыть эти диалоги. До доверенного совместимого UI — общая карточка версии/статуса/доступного управления.

## 3. Совместимость и границы проверки

HTTP/WSS/потоки — [API](<3. API и форматы данных.md.md>), module UI — [спецификация](<5. Модульная система.md.md>). Смежный Android SDK должен валидировать тот же schema/version/unit profile; schema-valid клиент ещё не доказывает secure storage/WorkManager/TLS/trust/import. Фон15/30/60мин/off без внешнего сервиса — нет гарантии времени доставки при Doze/force-stop/offline. Проверка обновлений максимум раз/24ч, отключаемая.

Непосредственные противоречия в FR/NFR исправлены точечно; для остальных перечисленных затронутых правил это дополнение имеет приоритет над прежней формулировкой. При последующей редакции UX переносить актуальное правило из дополнения, не возвращать старые гарантии. V-CLIENT/E10/E12 остаются не выполненными.
