# ServerDeck Agent

Нативный Linux-сервис на Go для мониторинга и управления серверами из Android-приложения ServerDeck. Agent работает непосредственно на сервере и предоставляет HTTPS/WSS API и локальный CLI. Обязательного облачного backend нет.

> **Статус: в разработке.** E01–E05, E07 и E08 закрыты в заявленных границах проверок. E06 реализован частично и требует испытаний на реальном оборудовании и сервисах. E09–E12 ещё предстоят. Готовность производственного выпуска не объявлена.

## Что реализовано

- **Мониторинг:** общий сбор system/CPU/RAM/файловых систем/сети/процессов, снимки, история, правила событий и активные проблемы.
- **Доверие и транспорт:** TLS, сопряжение устройств, отдельные отзываемые credentials, HTTPS/WSS и локальный Unix socket.
- **Операции и аудит:** SQLite, сохранение намерения до изменения, устойчивые operation ID, защита от повторного эффекта, блокировки и восстановление после сбоя.
- **Процессы и диагностика:** отдельные подтверждаемые TERM/KILL через pidfd и ограниченные ICMP-проверки.
- **Файлы:** разрешённые корни, просмотр и передача, создание/редактирование/переименование, перенос, приватная корзина, восстановление и отдельный PURGE. Есть аудируемая очистка и offline reconciliation неопределённых операций.
- **Интеграции:** адаптеры NVIDIA NVML, Docker read-only и поддерживаемых источников системных событий. Их аппаратные и эксплуатационные проверки ещё не завершены.

Agent действует с правами выбранного существующего пользователя Linux. Root допускается, но защита собственных ключей, состояния и рабочих объектов сохраняется. API произвольных shell-команд отсутствует. Отказ аудита блокирует изменения, сохраняя возможность мониторинга.

## Сборка для разработки

Один Go-модуль расположен в `agent/`; согласованное имя — `serverdeck.local/agent`. Две точки входа: `serverdeck-agent` и `serverdeckctl`.

Проверенный builder: Ubuntu 22.04 WSL2 amd64, **Go 1.27.2**, **GCC 11.4.0**, glibc 2.35, **cgo включён**. Для проверки ELF требуется `readelf`, для build inspector — Python 3. Точные версии, происхождение инструментов и подготовка окружения описаны в [BUILD.md](agent/BUILD.md); команды ниже предполагают уже подготовленное окружение.

```bash
cd agent
export GOTOOLCHAIN=local CGO_ENABLED=1 CC=/usr/bin/gcc-11

go mod verify
go vet ./...
go test ./...
go test -race ./...

bash tools/build-linux.sh amd64
./dist/linux-amd64/serverdeck-agent version
./dist/linux-amd64/serverdeckctl sqlite-info
```

Результат: `agent/dist/linux-amd64/serverdeck-agent` и `serverdeckctl`. Бинарные файлы и локальное окружение сборки не включены в Git. Сборка использует встроенную SQLite; полностью статическая переносимость не обещается. Для arm64 нужна отдельная cgo cross-chain — см. BUILD.md.

Это порядок разработки, а не инструкция установки на рабочий сервер: production install/update lifecycle относится к E11.

## Проверки и ограничения

[Итоговый E08 evidence](agent/evidence/E08-final-wsl-2026-10-16/README.md) содержит команды, версии и SHA-256 проверенного снимка. В Ubuntu WSL2 прошли vet, общие тесты, race, fuzz, cgo сборки amd64/arm64, ELF-проверки и smoke собранных amd64 команд. Специальные файловые сценарии проверены с реальными SQLite-БД и effects, включая сбои аудита, crash/replay, конкуренцию, ограниченный ENOSPC, read-only и защиту собственных объектов при root.

- WSL-проверки относятся к указанному окружению, а не всей матрице обычных Linux-серверов.
- Arm64 cross-build не заменяет нативные ARM-тесты; они запланированы в E12.
- Реальные GPU/Docker/security matrix, production systemd и Android-интеграция ещё требуют проверок.
- Файловые версии проверяются перед атомарной публикацией, но остаётся согласованная гонка с внешними SSH writers. Собственные деревья Agent переносятся при остановленном Agent; подробная модель — в [FILES.md](agent/FILES.md).

Evidence сохраняет исторические снимки: последующее изменение кода или документации не делает прежние результаты проверкой новой версии.
